# Removing the custom kernel from the machine

How to take the kernel built for this project (`7.2.12-netquota`, and a plain
`7.2.12` if one was built earlier) off the Ubuntu 24.04 test machine, so that
only the stock Ubuntu kernels remain. It follows `setup-and-build.md`, which
installed the kernel with `make modules_install && make install &&
update-grub`.

This page is about the **installed kernel and the build leftovers**. For
taking the system call out of the kernel *source* and rebuilding, see
`removing-net-quota.md`.

None of this touches your own files. It removes the custom kernel, its boot
entry, and optionally the source tree.

The commands below were written from how a manual `make install` lays files
out on Ubuntu and have not been run on the test machine. Each step starts by
listing what exists, so look at the listing before deleting.

## What the install put on the machine

`make modules_install` and `make install` are not package installs, so
`apt remove` does not know about them and will not clean them up. For a kernel
release called `REL` (for example `7.2.12-netquota`) they leave:

| Where | What |
|---|---|
| `/boot/vmlinuz-REL` | the kernel image |
| `/boot/initrd.img-REL` | the initial RAM disk, made by `update-initramfs` |
| `/boot/System.map-REL`, `/boot/config-REL` | symbol map and the build config |
| `/lib/modules/REL/` | the modules (a few hundred MB) |
| `/boot/grub/grub.cfg` | the GRUB menu entries, regenerated by `update-grub` |
| `/usr/src/linux-7.2.12/` | the source tree and all build output (many GB) |

## 1. Start from a stock kernel

You must not remove the kernel that is running.

```bash
uname -r
```

If it prints `7.2.12-netquota` (or `7.2.12`), reboot, hold `Shift` (BIOS) or
press `Esc` (UEFI) at start-up to get the GRUB menu, choose *Advanced options
for Ubuntu* and pick an entry that is a stock Ubuntu kernel (a number such as
`6.8.0-xx-generic`). Run `uname -r` again to confirm.

Then check that at least one stock kernel is installed and is the one you
booted:

```bash
dpkg -l 'linux-image-*' | grep '^ii'
ls /boot/vmlinuz-*
```

If no `linux-image-*` package is listed, **stop**: removing the custom kernel
would leave the machine with nothing to boot. Install one first with
`apt install linux-image-generic`.

## 2. List what is installed for the custom kernel

Do this once per release you want to remove. Use the exact name from the
`ls /boot/vmlinuz-*` output.

```bash
REL=7.2.12-netquota
ls -ld /boot/*-"$REL" /boot/*-"$REL".old /lib/modules/"$REL" \
       /var/lib/initramfs-tools/"$REL" 2>/dev/null
```

You should see the files from the table above (the `.old` files and the last
path may not exist). The patterns end exactly at `REL`, so `7.2.12` does not
match files of `7.2.12-netquota`, and the other way round. If the output shows
anything that is not part of that kernel, stop and look before going on.

## 3. Remove the files

```bash
REL=7.2.12-netquota        # then repeat for 7.2.12 if you built that one too

update-initramfs -d -k "$REL"
rm -f  /boot/vmlinuz-"$REL" /boot/System.map-"$REL" /boot/config-"$REL"
rm -f  /boot/vmlinuz-"$REL".old /boot/initrd.img-"$REL".old \
       /boot/System.map-"$REL".old /boot/config-"$REL".old
rm -rf /lib/modules/"$REL"
rm -rf /var/lib/initramfs-tools/"$REL"
```

`update-initramfs -d` deletes `/boot/initrd.img-REL`. Two commands may report
that a file is missing; that is fine, it means that piece was never created.

Out-of-tree drivers built with DKMS (an NVIDIA driver, for example) may have
been built for the custom kernel as well:

```bash
dkms status | grep "$REL"
```

If that prints anything, remove each entry with
`dkms remove <module>/<version> -k "$REL"`. If it prints nothing, there is
nothing to do.

## 4. Rebuild the GRUB menu

```bash
update-grub
grep -c netquota /boot/grub/grub.cfg     # expect 0
grep -E '^\s*(menuentry|submenu)' /boot/grub/grub.cfg | cut -c1-90
```

The count must be `0` and the list must show only the stock kernels (and
recovery entries for them). If your machine boots with a saved or numbered
default, check that it still points at the entry you want:

```bash
grep -E '^GRUB_DEFAULT|^GRUB_SAVEDEFAULT' /etc/default/grub
```

`GRUB_DEFAULT=0` means the first entry (the newest stock kernel) and needs no
change. If it holds a number that you set while testing, set it back to `0`
(or `saved` together with `grub-set-default 0`) and run `update-grub` again.

## 5. Optional: free the disk space of the build

Only if you do not need to rebuild. The source tree with its build output is
by far the largest piece.

```bash
du -sh /usr/src/linux-7.2.12
rm -rf /usr/src/linux-7.2.12
```

Also delete the downloaded tarball (`linux-7.2.12.tar.xz`, or whichever name
and place you downloaded it to) if it is still around. If you might test again
later, keep the tree and the tarball: rebuilding from scratch takes a long
time, while rebuilding after a small change is quick.

Do not delete the project repository (`net-quota-syscall`). It does not
depend on the installed kernel.

## 6. Optional: tidy the project's user-space side

The tests and tools in `user-code/` only work on the net_quota kernel. On a
stock kernel they report "Function not implemented". To clear the build
output:

```bash
cd /path/to/net-quota-syscall/user-code && make clean
```

If you copied built binaries anywhere else, remove those copies too.

## 7. Check the result

```bash
uname -r                                          # a stock kernel
ls /boot | grep -c netquota                       # 0
ls /lib/modules | grep -c netquota                # 0
grep -c netquota /boot/grub/grub.cfg              # 0
```

Reboot once to confirm that the machine comes up on its own, without the
GRUB menu, on the stock kernel.

## If something goes wrong

- **A "No such file" message from `rm` or `update-initramfs -d`:** harmless,
  that file was not there.
- **The custom entry is still in the GRUB menu:** `update-grub` was not run as
  root, or `/boot/grub/grub.cfg` was not rewritten. Run it again with `sudo`
  and re-check with the `grep` in step 4.
- **The machine does not boot after removal:** at the GRUB menu choose
  *Advanced options* and pick another kernel, or the *recovery mode* entry. If
  there is no usable entry, boot from an Ubuntu installer USB stick, mount the
  system disk, `chroot` into it and run `apt install --reinstall
  linux-image-generic` followed by `update-grub`.
- **You removed the running kernel by mistake:** the machine keeps running
  until the next reboot. Do not reboot yet. Install a stock kernel
  (`apt install --reinstall linux-image-generic`), run `update-grub`, then
  reboot.
